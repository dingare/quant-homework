# DP Revisit — 从递归枚举到状态合并

## 1. DP 究竟省掉了什么

先问：“如果允许我枚举所有合法决策，我怎么得到答案？”每个选择会通向一个剩余问题。递归树中，许多不同历史可能通向同一个剩余问题。若它们未来可做的选择和未来收益规则相同，就可用一个状态代表它们，只计算一次。递归树由此合并成状态依赖图。

这要求找出**足够的状态**。判断方法：任取两条到达同一状态的历史，接下来的合法选择、状态转移和新增收益是否相同？如果不同，就丢了必要信息。前缀 DP 则是在同样的未来条件下，只保留过去价值最好的历史；较差历史不可能通过相同的未来延续反超。

“最优”不是 DP 的充分条件。贪心需要证明局部选择安全；有些优化是排序、二分或图算法。反过来，DP 也能回答可行性、计数、概率，并不一定取最大或最小。没有可复用子问题时，记忆化也未必省时间；存在循环依赖时，不能直接套有限 DAG 的一次倒推。

## 2. 实际走一遍：House Robber 的小例子

给定 `[2,7,9,3,1]`，不能同时选相邻位置。先不用表格，定义：

**F(i)：从位置 i 到末尾可获得的最大新增总和，且位置 i 没有被之前的选择禁用。**

在 i 可以跳过，或选择后直接跳到 i+2：

```math
F(i)=\max\{F(i+1),\ a_i+F(i+2)\},\qquad
F(i)=0\quad(i\ge n).
```

为什么只需 i？调用 F(i) 已保证 i 可选；前面已经获得的钱只会作为一个加数返回，不改变后面的合法性。若递归改成“每天只前进一格”，就必须加上上一位置是否已选，不能仍然仅存 i。

递归树的开头：

```text
F(0)
├─ 跳过 0 → F(1)
│           ├─ 跳过 1 → F(2)
│           └─ 选择 1 → 7 + F(3)
└─ 选择 0 → 2 + F(2)   ← 与上面的 F(2) 完全同一剩余问题
```

无缓存会反复算 F(2)、F(3) 等；有缓存后最多 n 个非终止状态，每个只检查两个选择，时间为 $`O(n)`$。

| i | 5 及以后 | 4 | 3 | 2 | 1 | 0 |
| --- | --- | --- | --- | --- | --- | --- |
| F(i) | 0 | 1 | 3 | 10 | 10 | 12 |

比如 F(2) 取 `max(3, 9+1)=10`。从右向左计算，是因为 F(i) 依赖右侧已经完成的两个状态，答案在 F(0)。

同一题也可定义 **D(k)：只允许使用前 k 个位置的最大总和**。D(0)=0，D(1)=2，依次得到 `[0,2,7,11,11,12]`。它与 F(i) 的语义不同，不能把两套下标和 base case 混写。练习题 Q1 使用这套前缀定义。

## 3. 从递归到两种实现

Memoization 是“调用到某状态时，再递归求它并缓存”：

```python
from functools import cache

def rob_top_down(nums):
    @cache
    def future(i):
        if i >= len(nums):
            return 0
        return max(future(i + 1), nums[i] + future(i + 2))
    return future(0)
```

Tabulation 是“先列出状态的依赖顺序，主动填表”：

```python
def rob_bottom_up(nums):
    n = len(nums)
    future = [0] * (n + 2)
    for i in range(n - 1, -1, -1):
        future[i] = max(future[i + 1], nums[i] + future[i + 2])
    return future[0]
```

两者求的是同一个状态函数。Memoization 可能只访问可达状态，但有缓存与函数调用开销，深链还可能触发 Python 递归深度限制；tabulation 无递归栈，计算顺序需要自己保证。上面两版时间都为 $`O(n)`$，辅助空间都为 $`O(n)`$，递归版必须把调用栈算进去。只依赖最近两格时，还能压到常数空间；先证明状态和顺序，再压缩。

## 4. 面试时按这个顺序推导

| 步骤 | 要说清的话 | 自检 |
| --- | --- | --- |
| 枚举 | 当前有哪些合法选择？每个选择留下什么？ | 是否漏掉“什么也不做”？ |
| 状态 | “这一个单元格表示……” | 同状态的不同历史，未来是否等价？ |
| 价值 | 求最优、是否可达、还是方案数？ | 累积收益在状态值里，还是函数参数里？ |
| 转移 | 按第一步或最后一步，把解分组 | 子状态是否与原定义完全一致？ |
| 边界 | 空前缀、空区间、第一天、金额 0 | 下标恰好越界时意味着什么？ |
| 不可能 | 不可达是 +∞、−∞ 还是 False？ | 是否错误地用 0 伪造了合法解？ |
| 顺序 | 先算所有依赖，再算当前格 | 一维覆盖后，读到的是上一层还是本层？ |
| 答案 | 指定哪个格或哪些格的最大值 | LIS 通常不在最后一个格；股票不能以持仓结束 |
| 证明 | 边界正确，转移覆盖合法解且可实现 | 能否用更优子解替换原子解？ |
| 成本 | 状态数 × 每状态转移成本 | 排序、二分、缓存和递归栈都算了吗？ |

最小硬币数的不可达金额初始化为正无穷，因为是在取最小值；股票“未交易前已持仓”初始化为负无穷，因为是在取最大值；子集可行性用 False。它们不是可互换的模板。计数 DP 往往以空方案计数为 1；不能机械照抄最优值 DP 的零边界。

## 5. 怎样证明递推正确

以 House Robber 为例，对允许使用的前缀长度归纳：

1. 空前缀和单元素前缀的答案显然正确。
2. 任意合法解要么不含最后一个位置，要么含它。这两类覆盖所有解，且按是否含该位置互斥。
3. 第一类最多得到前 k−1 个位置的最优值；第二类不能含倒数第二个位置，所以最多是最后一个值加上前 k−2 个位置的最优值。
4. 两个候选都能由合法子解构造出来，取最大值既是上界，也能达到。

对 Coin Change 按“最后一枚硬币”分组；对 LIS 按“倒数第二个位置”分组；对股票按“昨日状态与今日动作”分组；对博弈按“当前玩家拿哪端”分组。不要只说“具有最优子结构”而不解释可替换性。

“不重复”也要分情况：最优值 / 布尔 DP 中，多条转移到达同一状态是允许的，因为 max、min、or 不因重复而改变结果。计数 DP 用加法，重复枚举同一对象会改变答案，必须明确数的是排列还是组合。状态合并解决的是重复计算，不自动解决重复计数。

## 6. 两个最常丢失的信息

**状态过少：** 股票的“当天不持仓”不足以判断明天能否买入；今天刚卖出和已休息一天的历史拥有不同的未来动作。需要加一类状态，或让卖出后的递归跨过冷冻日。

**状态过多：** 零和轮流取数若保存双方历史总分，会把已经结束的过去带入状态。用“当前行动玩家减另一玩家的未来分差”后，剩余区间就足够；换手时减去对方最优分差。

## 7. Optional：有限期决策的联系

有限期 DP 的抽象形式是“当前即时收益 + 下一状态价值”，最后一期给定终值。若在给定当前状态和动作后，未来的条件分布不再依赖更早历史，就可做 Bellman 倒推：

```math
V_t(s)=\max_{a\in A_t(s)}
\left\{r_t(s,a)+\mathbb E[V_{t+1}(S')\mid s,a]\right\}.
```

逻辑题常是确定性转移，期望符号就消失了。Toy extension：每天有限预算选择一个研究项目，项目消耗一单位预算，当期收益已知且不能连续两天执行。可以尝试定义“日期、剩余预算、昨天是否执行”的状态，并设最后一天之后的价值为 0；若收益模型还依赖某个未记录的环境变量，就要把它或其充分信息加入状态。这只是状态设计练习。
